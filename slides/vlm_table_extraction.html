FEATURE BRANCH — vlm-table-extraction

VLM Tablo Çıkarma

Taranmış ve döndürülmüş tabloları yerel bir Görü-Dil Modeli (Vision-Language Model) ile okunabilir markdown'a çeviren yeni ingestion katmanı.

🔍 Otomatik Tespit

Bozuk tabloları kalite analiziyle saptar, düzgün olanlara dokunmaz.

🖼️ Görsel İşleme

Yüksek-çözünürlük kırpma, dik çevirme ve bant bölme.

🤖 Yerel VLM

Ollama üzerinde qwen2.5vl — bulut bağımlılığı sıfır.

Problem: OCR'ın Çöktüğü Tablolar

TBMM bütçe icmal tabloları gibi taranmış ve 90° döndürülmüş tablolar mevcut pipeline'da iki noktada başarısız oluyordu:

1. TableFormer Başarısızlığı
Docling'in yapısal tablo modeli (TableFormer) döndürülmüş görüntülerde satır/sütun yapısını çıkaramıyor → num_rows = 0, num_cols = 0.
2. OCR Çöp Çıktısı
EasyOCR/Tesseract döndürülmüş metni yanlış okuyor → Tek-karakter hücreler, anlamsız parçalanmış metin. Ör: | ğ | 5 1 1 1 |
ETKİSİ
Retrieval Kalitesi Düşer: Bozuk tablo metni vektör uzayında anlamsız temsil edilir.
Yanıtlar Yanlışlaşır: LLM, çöp tablolardan doğru rakam/isim çıkaramaz.
Sayısal Doğruluk Sıfır: Bütçe tutarları, oy dağılımları tamamen kaybolur.
Çözüm: Bozuk tabloları otomatik tespit et → yüksek-çözünürlüklü görüntüyü bir Görü-Dil Modeli'ne gönder → temiz markdown tablo al.

Çözüm Mimarisi

VLM tablo çıkarma, mevcut parse katmanına (KATMAN 1) entegre bir post-process adımıdır. Düzgün tablolara dokunmaz; yalnızca bozuk tespit edilenleri düzeltir.

Anahtar Tasarım Kararı: VLM yalnızca table_is_low_quality() == True döndüğünde devreye girer. Düzgün okunan tablolara dokunulmaz — gereksiz VLM maliyeti sıfır.

VLM Nasıl Tetiklenir?

3 KATMANLI TETİKLEME
1

Global Anahtar

VLM_TABLE_EXTRACTION=1 (varsayılan aktif). 0 yapılırsa tüm VLM işlemi devre dışı kalır.

2

Kalite Filtresi — table_is_low_quality()

Sadece label == "table" olan atomlar incelenir. Tetikleyiciler:

TableFormer yapı çıkaramamış: num_rows == 0 veya num_cols == 0
OCR çöp çıktısı: Hücrelerin ≥%50'si tek karakter veya toplam hücre < 4
3

Geometri Kontrolü

Tablo atomunun geçerli bbox ve page bilgisi olmalı. Yoksa atom atlanır, orijinal metin korunur.

KOD AKIŞI 
# markdown_converter.py  (satır 211-225)

# VLM table extraction integration
vlm_applied = False
if self.use_vlm and atoms_data:
    from vlm_table_extractor import (
        process_atoms_with_vlm,
        table_is_low_quality,
    )
    if any(table_is_low_quality(a)
           for a in atoms_data):
        atoms_data = process_atoms_with_vlm(
            file_path, atoms_data,
            self.ollama_url, self.ollama_model
        )
        full_text = "\n\n".join(
            a["text"] for a in atoms_data
        )
        vlm_applied = True
Cache Güvenliği: VLM açıkken cache anahtarı _vlm-{model} etiketiyle yeniden hesaplanır. Eski (VLM'siz) cache'ler yanlışlıkla kullanılmaz.

Görsel İşleme Hattı

Her bozuk tablo atomu için aşağıdaki görsel ön-işleme zinciri çalışır:

ADIM 1

Yüksek-Çözünürlük Kırpma

PyMuPDF ile tablo bbox'ı orijinal PDF sayfasından 3× zoom ile kırpılır. BOTTOMLEFT→TOPLEFT koordinat dönüşümü otomatik.

crop_table_image() → PNG bytes
ADIM 2

Dik Çevirme (Deskew)

Tesseract OSD ile yön açısı tespit edilir. Güven eşiği altındaysa aspect-ratio fallback: portre (h>w) ise 90° çevir.

deskew_to_upright() → PNG bytes
ADIM 3

Bant Bölme (Tiling)

Dik görüntü 1600px'i aşarsa yatay bantlara bölünür. 2..N bantlara başlık şeridi (95px) eklenir → sütun kayması önlenir.

_split_into_bands() → Image list
Hata Toleransı: Her adım try/except sarmalıdır. Tesseract yüklü değilse → fallback. Kırpma başarısızsa → orijinal metin korunur. Hiçbir hata ölümcül değildir.

Konfigürasyon & Parametreler

Tüm VLM parametreleri settings.py içinde tanımlıdır ve .env ortam değişkenleriyle ezilebilir:

Değişken Açıklama Varsayılan
VLM_TABLE_EXTRACTION Ana açma/kapama anahtarı 1 (aktif)
VLM_TABLE_MODEL Ollama'daki VLM modeli qwen2.5vl:7b
VLM_TABLE_ZOOM PDF → görüntü render ölçeği 3.0
VLM_TABLE_NUM_CTX Ollama bağlam penceresi (KV boyutu) 16384
VLM_TABLE_NUM_PREDICT Maksimum üretim token sayısı 8192
VLM_TABLE_TIMEOUT HTTP zaman aşımı (saniye) 900
VLM_TABLE_TILE_MAX_HEIGHT_PX Bantlama eşiği (piksel) 1600
VLM_TABLE_AUTOROTATE OSD otomatik dik çevirme 1 (aktif)
Yüksek Doğruluk İçin: VLM_TABLE_MODEL=qwen2.5vl:32b — 32B model ~4× yavaş ama sayısal tutarlılık bire bir doğrulanmıştır.

Nasıl Çalıştırılır?

🖥️ Yöntem A: Tekil PDF (CLI)

Doğrudan MarkdownConverter CLI aracıyla tek bir PDF test edilir.

# 1. Ollama VLM modelini çek
ollama pull qwen2.5vl:7b

# 2. VLM ile parse et
python -m src.common.parsing.markdown_converter \
  --file belge.pdf \
  --use-vlm \
  --force

# 3. İsteğe bağlı: farklı model
python -m src.common.parsing.markdown_converter \
  --file belge.pdf \
  --use-vlm \
  --ollama-model qwen2.5vl:32b
Not: --force parametresi cache'i temizler. Onsuz eski (VLM'siz) cache kullanılabilir.

⚙️ Yöntem B: Ingestion Pipeline

Tüm veri alma akışında VLM otomatik devreye girer (VLM_TABLE_EXTRACTION=1 varsayılan).

# Standart ingestion — VLM otomatik
python -m src.trainer.ingestion.ingest \
  --request manifest.json

# VLM'i kapatmak istersen:
VLM_TABLE_EXTRACTION=0 \
  python -m src.trainer.ingestion.ingest \
  --request manifest.json
Entegrasyon: DoclingManager başlatılırken settings.VLM_TABLE_EXTRACTION okunur → tüm adapter'lar (tutanak, kanun teklifi, PDF rapor) otomatik olarak bu ayarı miras alır.
